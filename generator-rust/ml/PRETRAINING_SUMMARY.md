# Mazle Puzzle Generator - Pretraining Summary
## Problem Statement

**Goal:** Train a neural network to replace the Rust-based puzzle generator, producing valid ice puzzles faster than the current ~10-60  minute generation time.

**Success Criteria:** Generated puzzles must pass ALL of these criteria:
1. **valid_structure** - Exactly 1 START tile and exactly 1 GOAL tile
2. **solvable** - A path exists from START to GOAL
3. **no_stuck** - No tiles where the player gets permanently stuck
4. **unique_optimal** - Exactly ONE optimal path (no ties)
5. **target_10** - Optimal path is exactly 10 moves

---

## Input Data Structure

### Dataset
- **Size:** 200,000 valid puzzles generated by Rust generator
- **File:** `train-combined-200k-shuf.jsonl`
- **Format:** JSONL (one JSON object per line)

### Sample Record
```json
{
  "seed": "puzzle-12345",
  "width": 13,
  "height": 13,
  "tiles": [[4,4,1,4,...], [4,1,4,4,...], ...],
  "start": [3, 5],
  "goal": [10, 8],
  "optimal_moves": 10
}
```

### Tile Types (Vocabulary)
| ID | Type | Description |
|----|------|-------------|
| 0 | Floor | Player steps one tile |
| 1 | Wall | Impassable |
| 4 | Ice | Player slides until hitting obstacle |
| 5 | Ledge_U | One-way, can only enter from above |
| 6 | Ledge_D | One-way, can only enter from below |
| 7 | Ledge_L | One-way, can only enter from left |
| 8 | Ledge_R | One-way, can only enter from right |
| 100 | START | Player starting position |
| 101 | GOAL | Target destination |

### Tile Distribution (Training Data)
- Ice: **72.8%** (majority class)
- Wall: **17.8%**
- Ledges: ~1.9% each (7.6% total)
- Floor: 0.5%
- START: 0.6% (exactly 1 per puzzle = 1/169)
- GOAL: 0.6% (exactly 1 per puzzle = 1/169)

### Grid Structure
- **Size:** 13x13 = 169 tiles
- **Border:** Always walls (implicit or explicit)
- **Interior:** Mix of ice, walls, ledges, floor

## Approaches Tried

### 1. Feedforward CNN (Original)

**Architecture:**
- CNN encoder for tile grid
- Separate heads for tiles, start position, goal position
- Seed conditioning via projection

**Training:**
- Standard cross-entropy loss
- Class weights to handle imbalance

**Results:**
- tile_acc: ~70%
- start_acc: 3.7%
- goal_acc: 7.7%
- NaN loss instability at ~5000 steps

**Problems:**
- Start/goal heads couldn't learn 1-of-169 position
- Architecture couldn't condition on previous tile predictions
- Model collapsed to predicting majority class (ice)

---

### 2. Feedforward with Integrated Start/Goal

**Change:** Merged START (100) and GOAL (101) into the tile vocabulary instead of separate position heads.

**Results:**
- Still collapsed to all-ice predictions
- Couldn't learn the exactly-1 constraint

**Problems:**
- Same fundamental issue: no conditioning between positions

---

### 3. Autoregressive Transformer (AR)

**Architecture:**
- Transformer decoder (causal attention)
- Predicts tiles left-to-right, top-to-bottom as sequence
- Each position conditioned on all previous positions
- Seed conditioning via latent vector

**Presets:**
- Base: 6.4M params (256 dim, 6 layers, 8 heads)
- Large: 18.5M params
- XL: 40.5M params

**Training:**
- Teacher forcing (ground truth as input)
- Cross-entropy loss per position

**Results (Base, step 6000):**
- Loss plateaued at ~0.93
- valid_structure: 13%
- solvable: 7%
- full_pass: 0%

**Problems:**
- Loss = 0.93 is essentially log(1/0.73) = predicting ice 73% of the time
- Model learned marginal distribution, not conditional structure
- Greedy decoding always picks ice (highest probability)
- Temperature sampling produces correct counts on average but non-deterministic

---

### 4. AR + Class Weights (Ice Weight = 0)

**Change:** Set ice loss weight to 0, high weights for rare tiles.

**Results:**
- Model spammed walls instead of ice
- No improvement in valid puzzles

**Problem:** Removing ice penalty entirely caused opposite problem.

---

### 5. AR + Auxiliary Losses ⭐ (Best AR Approach)

**Changes:**
- Equal cross-entropy weights (no class weighting)
- Added auxiliary losses on softmax probabilities:
  - `start_penalty = |sum(p_start) - 1|` (expected START count should be 1)
  - `goal_penalty = |sum(p_goal) - 1|` (expected GOAL count should be 1)
  - `kl_loss = KL(target_dist || pred_dist)` (match training tile distribution)
- Combined: `loss = CE + 2.0*start + 2.0*goal + 0.5*KL`

**Results (step 2000):**
- valid_structure: **18%**
- solvable: **13%**
- no_stuck: 6%
- unique_optimal: **11%**
- target_10: 1%
- **full_pass: 1%** ✓

**Why it helped:** Auxiliary losses directly encode constraints on probabilities, which are differentiable. Model gets gradient signal for "you're predicting 3 STARTs, should be 1."

---

### 6. AR + Auxiliary Losses + Scheduled Sampling

**Change:** During training, randomly replace ground truth with model's own predictions to reduce exposure bias.

**Schedule:** `sample_prob = min(0.5, epoch / (epochs * 2))`

**Results (step 6000):**
- valid_structure: 13%
- solvable: 7%
- full_pass: 0%

**Problem:** Made results worse, not better. May need different schedule or more tuning.

---

### 7. Discrete Diffusion ⭐ (Current Best Potential)

**Architecture:**
- U-Net style CNN with residual blocks
- Absorbing state diffusion (MASK token)
- Forward process: randomly mask tiles
- Reverse process: iteratively unmask/predict
- 100 diffusion timesteps
- 10.8M params (base preset)

**Key Insight:** Sees entire grid at each step, no sequential dependency. Can globally reason about structure.

**Training:**
- Random timestep t per sample
- Predict original tiles from corrupted (partially masked) input
- Cross-entropy + count penalties for START/GOAL

**Results (step 4000, ~1.3 epochs):**
- valid_structure: **14%**
- solvable: **8%**
- no_stuck: **6%**
- unique_optimal: 6%
- target_10: 1%
- **full_pass: 1%** ✓

**Status:** Deprecated. See V2 approach below.

---

### 8. V2 Architecture ⭐⭐ (CURRENT BEST)

**Key architectural changes based on research:**

1. **No seed conditioning** - Seed only controls sampling RNG, not input features
   - Prevents "learning pseudo-random function" trap
   - Model learns distribution, not seed→puzzle mapping

2. **Separate START/GOAL position heads** - 169-way categorical each
   - Constraint "exactly 1 START/GOAL" is now BY CONSTRUCTION
   - Model samples position first, then generates tiles

3. **Tiles conditioned on fixed positions**
   - Tile grid generated after START/GOAL are known
   - No START/GOAL in tile vocabulary (simpler loss)

4. **BERT-style masked diffusion** (not autoregressive)
   - Sees entire grid at each step
   - Global reasoning about structure

5. **Deterministic seeded sampling**
   - Gumbel-max trick with torch.Generator
   - Same seed → same puzzle (reproducible)

6. **Generate-many + verifier filter ready**
   - `generate_k_candidates()` method built-in
   - Weighted replay buffer for verifier-aware fine-tuning

**Architecture:**
- Transformer encoder (not decoder)
- 5.4M params (base preset: 256 dim, 6 layers, 8 heads)
- 50 diffusion timesteps

**Results (step 5000, ~1.6 epochs):**
- valid_structure: **100%** ✓ (by construction!)
- solvable: **77-86%** (vs 7-13% in v1)
- no_stuck: **64-70%**
- unique_optimal: **67-73%** (vs 6-11% in v1)
- target_10: 0-2%
- full_pass: 0-2%

**Why V2 is dramatically better:**
- valid_structure 100% vs 13-18% in v1 (architecture fix)
- solvable 80%+ vs 7-13% (removing seed conditioning)
- Position losses near-zero after 1000 steps

## Key Learnings

### 1. Seed Conditioning Was The Problem
Conditioning on seed strings caused model to try learning a pseudo-random function (200k IDs → 200k grids). Impossible to learn, so model defaulted to marginal distribution (73% ice).

**Fix:** Use seed only for deterministic sampling RNG, not as model input.

### 2. Position Heads > Rare Tile Tokens
Making START/GOAL rare tokens in a 9-way tile vocabulary means the model must learn 1-of-169 × 1/169 probability. Very hard.

**Fix:** Separate 169-way position heads. Constraint "exactly 1" is now by construction.

### 3. Class Imbalance Still Matters
With 73% ice, tile prediction still trends toward ice. But V2's per-tile loss on 7-class vocabulary (no START/GOAL) is cleaner.

### 4. Global Models > Sequential Models
Transformer with full attention (not causal) sees entire grid. Much better for global constraints like path uniqueness.

### 5. Generate-Many + Filter is Fast Win
With ~80% solvable and 70% unique_optimal, generating K=10 candidates and filtering gets high throughput even with low per-puzzle pass rate.

## The Degradation Problem ⚠️

**Critical Discovery:** Longer training leads to simpler puzzles!

**Observed Behavior (without mitigations):**
| Step | solve% | moves mean | moves near 10 |
|------|--------|------------|---------------|
| 500 | 63% | 6.3 | 12% |
| 1500 | 86% | 5.2 | 8% |
| 2500 | 78% | 4.7 | 5% |
| 3000 | 75% | 4.0 | 3% |

**Root Cause:** Tile cross-entropy loss doesn't encode path length. Path length is a **global emergent property** of the entire grid configuration. The model minimizes loss by generating tiles that locally match the training distribution, but simpler global structures (shorter paths) are "easier" solutions to tile prediction.

**Why this happens:**
- Training data is all 10-move puzzles, so every tile position is trained on 10-move examples
- But the cross-entropy loss only cares about matching tile types at each position
- Shorter-path puzzles can still have similar tile distributions locally
- Model drifts toward configurations that are "easier" to predict while technically valid

---

## Degradation Mitigations Implemented

### 1. Exponential Moving Average (EMA)

**What:** Maintain averaged weights that smooth out noisy gradient updates.

**Implementation:**
- `EMA` class in pretrain_v2.py
- After each step: `shadow = decay * shadow + (1 - decay) * weights`
- Eval and saving use EMA weights

**Decay settings tested:**
- 0.999: ~500 step warmup, helped stabilize at ~5.0 moves but still drifted
- 0.9999: ~5000 step warmup, slower but more stable (currently testing)

**Result:** Slows degradation but doesn't fully prevent it alone.

---

### 2. Path Auxiliary Supervision ⭐

**Key Insight:** Even with constant 10-move labels, path GEOMETRY varies. Supervising the path structure forces the model to learn the underlying mechanism.

**Implementation:**
- Extended Rust verifier to return `optimal_path` (list of stop positions)
- Added two auxiliary heads:
  - `on_path_head`: Binary prediction for "is this cell on the optimal path?"
  - `is_stop_head`: Binary prediction for "is this cell a stop position?"
- Computed online during collate (~3% overhead)

**New losses:**
```python
on_path_loss = F.binary_cross_entropy_with_logits(on_path_logits, on_path_mask)
is_stop_loss = F.binary_cross_entropy_with_logits(is_stop_logits, is_stop_mask)
```

**Files modified:**
- `generator-rust/src/generators/ice.rs`: Added `find_optimal_path_public()`
- `generator-rust/ml/bridge/src/lib.rs`: Extended `ValidationResultPy` with path field
- `generator-rust/ml/model_v2.py`: Added auxiliary heads
- `generator-rust/ml/pretrain_v2.py`: Added path mask computation and losses

---

### 3. Data Augmentation (8-fold Symmetry)

**Implementation:** Apply random rotation and flips to each puzzle.

**Transformations:**
- 4 rotations: 0°, 90°, 180°, 270°
- 2 flips: horizontal, vertical (combined with rotation = 8 total)

**Ledge handling:** Ledges are directional, so must transform direction:
- Rotation 90° CW: up→left, left→down, down→right, right→up
- Flip horizontal: left↔right
- Flip vertical: up↔down

**Code:** `augment_puzzle()` function in pretrain_v2.py

**Result:** Helps prevent overfitting to specific orientations.

---

### 4. Learning Rate Floor

**Problem:** Cosine decay to 0 causes training to stall.

**Fix:** Added `--lr-min` argument (default 1e-6):
```python
lr = lr_min + 0.5 * (lr_max - lr_min) * (1 + cos(pi * step / total_steps))
```

## Post-Training Approaches Tried

### 9. Elite Fine-Tuning (FAILED)

**Concept:** Best-of-K selection + KL-anchored fine-tuning on verified puzzles.

**Implementation (`elite_finetune.py` - deleted):**
1. Generate K=50 candidates per seed
2. Score with verifier (exact-10 gets highest reward)
3. Fine-tune on highest-reward puzzles with KL anchor to prevent drift

**Results:**
- Exact-10 rate stuck at ~1.3% per round, not improving
- Model learned to copy elite tiles but not the underlying structure
- Cross-entropy on tiles doesn't encode WHY puzzles are good

**Why it failed:** Same fundamental issue as pretraining - tile loss doesn't capture move count. Copying tiles from good puzzles doesn't teach the model what makes them good.

---

### 10. REINFORCE RL Fine-Tuning (FAILED)

**Concept:** Policy gradient RL with verifier reward signal.

**Implementation (`rl_finetune.py`):**
- Track log-probabilities during masked diffusion generation
- For each tile: `log_prob_accum += log_softmax(logits)[chosen_tile]`
- Policy gradient: `loss = -(advantage * log_probs).mean()`
- KL penalty to anchor to pretrained model
- Entropy bonus for exploration

**Reward shaping:**
| Condition | Reward |
|-----------|--------|
| Not solvable | -1.0 |
| Has stuck tiles | -1.0 |
| Not unique optimal | -0.5 |
| Exact 10 moves | +1.0 |
| Near target (±1 move) | +0.3 |
| Off target | -0.2 per move |

**Results (500 steps training):**

*First run (bug: missing `no_stuck` in eval):*
- Eval showed: 70% → 80% (step 200) - appeared to improve
- But actual full pass: 46.7% vs pretrained 53.3% - **RL made it worse**

*Second run (fixed eval with `no_stuck`):*
| Step | Eval Full Pass |
|------|----------------|
| 0 | 66.7% (baseline) |
| 100 | 56.7% |
| 200 | still declining |

**Why it failed:**
1. **Extreme variance** - REINFORCE multiplies reward by log-prob of ALL 169 tiles. Even if one tile made the difference, all 169 get same update.
2. **Sparse reward** - Only ~6-19% of batch gets exact-10, so most gradients are noise
3. **Policy gradient ≈ 0** - Logs showed `pg=0.0000` every step, no learning signal
4. **KL anchor fights learning** - Model oscillates rather than improves
5. **Credit assignment impossible** - Can't isolate which tiles caused success/failure

## Key Learnings (Updated)

### 6. RL Doesn't Work With Diffusion Models (Easily)

**Problem:** Policy gradient methods need per-action credit assignment. Diffusion models make 169 tile decisions, all tangled together. REINFORCE treats the entire generation as one action, leading to:
- Extreme gradient variance
- No learning signal (pg ≈ 0)
- Worse performance than supervised pretraining

**What would work:** Per-tile rewards, but this requires knowing which tiles cause problems (only verifier knows this, and it's non-differentiable).

### 7. Degradation is Fundamental

Despite EMA, path heads, and augmentation, degradation still occurs. It's just delayed. The model finds "easier" solutions (shorter paths) that still minimize tile cross-entropy.

**Implication:** Must use early stopping or K-candidates filtering. Training longer always hurts eventually.

### 8. K-Candidates is Viable Production Strategy

With 66.7% success rate at K=100:
- Average 1.5 attempts per successful puzzle
- ~30 seconds per puzzle on MPS (acceptable)
- Can pre-generate daily puzzles in batch
- Deterministic for same seed

## 11. Classifier-Free Guidance (CFG) for Move Count Control ⭐⭐ (LATEST ATTEMPT)

### The Problem

The core bottleneck in v2 was identified as **move count control**. The model achieved excellent structural metrics (solve ~80%, unique ~70%) but couldn't consistently generate 10-move puzzles. The `t10%` metric stayed below 3% while `moves_mean` plateaued around 5.

**Root cause:** Training on only 10-move puzzles means the model never learns what distinguishes a 10-move puzzle from a 6-move puzzle. The local tile patterns look similar, so the model drifts toward "easier" configurations with shorter paths.

### The Solution: Classifier-Free Guidance

Implemented CFG conditioning on move count, allowing the model to learn the difference between puzzles of varying complexity.

**Key changes to `model_v2.py`:**
```python
# Move count range for conditioning (4-14 moves, plus null token)
MIN_MOVES = 4
MAX_MOVES = 14
NUM_MOVE_TOKENS = MAX_MOVES - MIN_MOVES + 2  # 4-14 + null = 12 tokens
NULL_MOVE_TOKEN = MAX_MOVES - MIN_MOVES + 1  # Index 11 = null/unconditional

# Move count embedding added to __init__
self.moves_embed = nn.Embedding(self.NUM_MOVE_TOKENS, config.model_dim)

# In forward(), moves embedding added to timestep embedding
if moves is not None:
    moves_emb = self.moves_embed(moves)
    t_emb = t_emb + moves_emb  # Combine with timestep

# In generate(), CFG formula applied:
if guidance_scale > 1.0:
    logits_cond = forward(x_t, t, start_pos, goal_pos, moves_cond)
    logits_uncond = forward(x_t, t, start_pos, goal_pos, moves_uncond)
    logits = logits_uncond + guidance_scale * (logits_cond - logits_uncond)
```

**Key changes to `pretrain_v2.py`:**
```python
# CollateFnV2 now extracts optimal_moves from data
optimal_moves = item.get("optimal_moves", 10)
move_token = optimal_moves_clamped - MIN_MOVES

# CFG dropout: 10% of time, replace with null token
if torch.rand(1).item() < cfg_dropout:
    move_token = NULL_MOVE_TOKEN

# Forward pass now includes moves conditioning
outputs = model(x_t, t, start_pos, goal_pos, moves)
```

### 9. Key Learnings (Updated)

### 9. Move Count is a "Global Property" Problem

The fundamental challenge: move count is determined by the *entire* grid configuration, not local patterns. CFG helps the model distinguish complexity levels, but the guidance signal is still weak because:
- The model predicts tiles independently at each position
- Path length emerges from the combination of all tiles
- Small changes to any tile can dramatically change optimal path length

### 10. CFG Needs Stronger Signal

With guidance_scale=2.0, the conditional and unconditional predictions may be too similar. Options to try:
- Higher guidance scale (3.0-5.0)
- Apply guidance to position heads too
- Train with higher CFG dropout (20-30%)
- Use guidance scheduling (higher early, lower late)

## 12. AdaLN + Move-Count Auxiliary Head (FAILED)

### Motivation

Standard CFG adds conditioning via simple embedding addition. Research on diffusion models (DiT, Stable Diffusion 3) shows that **Adaptive Layer Normalization (AdaLN)** provides stronger conditioning by modulating layer statistics rather than just adding to activations.

Additionally, we hypothesized that forcing the model to **predict move count from tiles** when conditioning is absent would create a stronger internal representation of complexity.

### Architecture Changes

**AdaLayerNorm (AdaLN):**
```python
class AdaLayerNorm(nn.Module):
    """LayerNorm with FiLM-style conditioning (AdaLN / AdaNorm)."""
    
    def __init__(self, dim: int, cond_dim: int):
        self.norm = nn.LayerNorm(dim, elementwise_affine=False)
        self.proj = nn.Linear(cond_dim, dim * 2)  # scale and shift
    
    def forward(self, x, cond):
        scale, shift = self.proj(cond).chunk(2, dim=-1)
        x = self.norm(x)
        return x * (1.0 + scale.unsqueeze(1)) + shift.unsqueeze(1)
```

**TransformerBlock changes:**
- Replaced standard `LayerNorm` with `AdaLayerNorm` in both pre-attention and pre-FFN positions
- Conditioning tensor (timestep + moves embedding) passed to every layer
- Removed the older approach of adding timestep embedding after attention

**Move-count auxiliary head:**
```python
# Predicts move count (4-14) from grid representation
self.moves_head = nn.Sequential(
    nn.Linear(config.model_dim, config.model_dim),
    nn.GELU(),
    nn.Linear(config.model_dim, self.NUM_MOVES),  # 11-way classification
)
```

**Training changes:**
- Separate `moves_cond` (with CFG dropout) and `moves_target` (always true label)
- Move-count loss computed ONLY on unconditional examples (when CFG dropout triggered)
- Removed stop sequence prediction (found unhelpful in prior experiments)

1. **Stronger conditioning ≠ better move control** - AdaLN makes the model more responsive to the conditioning signal, but the conditioning signal itself (move count token) doesn't contain enough information about HOW to achieve that move count
2. **Move-count head learned trivially** - Loss dropped to ~0.0000 almost immediately, meaning the head could predict move count from early layers without encoding useful structure

The model can easily learn to predict "this grid is a 10-move puzzle" from the grid itself, but it cannot learn "if I place ice here instead of wall, the path will be 2 moves longer."

## Phase 13: Path-Conditioned Training (Jan 2026)

After hitting the 2.7-3.1% ceiling, we tried a fundamentally different approach: **condition the tile generator on the ground-truth optimal path** from training data.

### Core Hypothesis

The model fails to produce 10-move puzzles because it can't "see" the intended path. By explicitly feeding the path as input conditioning, we test: **can the tile generator realize an explicit 10-move plan and preserve uniqueness?**

### Path Conditioning Implementation

**Two spatial encodings added to the model:**

1. **Stop-step one-hot features** (`stop_step_feat`): shape `[B, 13, 13, 11]`
   - For a 10-move puzzle (11 stops including start), channel `k` is 1.0 at the k-th stop position
   - Handles rare revisits (two channels can be 1 at same cell)

2. **On-path binary mask** (`on_path`): shape `[B, 13, 13, 1]`
   - 1.0 for every cell traversed by the optimal path (including slide intermediates)
   - Includes start and goal cells

**Model modifications** (in `model_v2.py`):
- Added `stop_step_proj = nn.Linear(11, model_dim)` and `on_path_proj = nn.Linear(1, model_dim)`
- Conditioning added to per-cell embeddings: `h = h + stop_step_proj(stop_feat) + on_path_proj(on_path_mask)`

**Augmentation:** Path coordinates transformed consistently with tile augmentation via `augment_puzzle_with_path()`.

### Auxiliary Losses

To ensure the model actually uses path conditioning, we added plan realization losses:

1. **L_stop** - Stop positions must be CLEAR (ice, floor, or ledge-accessible)
   - Penalizes walls at stop positions
   
2. **L_clear** - All traversed cells must be CLEAR
   - Ensures slides can actually occur between stops

Combined: `L_plan = λ_stop * L_stop + λ_clear * L_clear`

- Base: `model_v2.py` with path conditioning
- λ_stop = 0.15, λ_clear = 0.05 (fixed)
- LR: 1e-4
- EMA: 0.9999

## Phase 8: Conditioning Dropout Fine-Tuning

### The Problem

The model cannot generate puzzles from just a seed because it learned to depend on path input features. We need to convert it from path-conditioned to unconditional while preserving its 10-move generation capability.

### Solution: Classifier-Free Conditioning Dropout

Inspired by classifier-free guidance, we fine-tune the model by randomly dropping path conditioning during training while keeping the same auxiliary loss targets.

**Key insight:** The path features are used to compute loss targets (L_stop, L_clear, L_shortcut) regardless of whether they're passed to the model. This transfers "10-move discipline" into the unconditional pathway.

### Implementation

Added new training mode `--cond-dropout` in `pretrain_v2.py`:

```python
def train_cond_dropout(args, model, device, validate_fn, out_dir, config):
    """
    Fine-tune path-conditioned model to work without path conditioning.
    
    Randomly drops path features during training while keeping same loss targets.
    """
    # ... setup ...
    
    for batch in loader:
        # Compute conditioning dropout probability
        p_drop = get_cond_dropout_p(global_step, args)
        drop_mask = torch.rand(batch_size, device=device) < p_drop
        
        # Zero out path features for dropped samples
        stop_step_feat_masked = stop_step_feat.clone()
        on_path_masked = on_path.clone()
        stop_step_feat_masked[drop_mask] = 0.0
        on_path_masked[drop_mask] = 0.0
        
        # Forward with potentially zeroed conditioning
        outputs = model(x_t, t, start_pos, goal_pos,
                       stop_step_feat=stop_step_feat_masked,
                       on_path=on_path_masked)
        
        # Losses still computed using ground-truth paths (not masked)
        L_stop, L_clear = compute_plan_realization_loss(tile_logits, filtered_paths)
        # ... L_shortcut also uses GT paths ...
```

    # Steps 20k → 30k: p = 0.95 (mostly unconditioned)

## Appendix A: Current Model Architecture (PuzzleGeneratorV2)

### Overview

The model uses a **Transformer encoder with discrete diffusion** (BERT-style masked prediction). It generates a 13×13 tile grid given START/GOAL positions, optionally conditioned on an optimal path.

### Model Configuration (Base Preset)

| Parameter | Value | Description |
|-----------|-------|-------------|
| `model_dim` | 256 | Hidden dimension |
| `num_layers` | 6 | Transformer layers |
| `num_heads` | 8 | Attention heads |
| `ff_dim` | 1024 | Feedforward dimension (4× model_dim) |
| `tile_vocab_size` | 10 | Tile types (0-9 remapped) |
| `grid_size` | 169 | 13×13 tiles |
| `num_timesteps` | 50 | Diffusion steps |
| `mask_schedule` | cosine | Masking probability over time |
| **Total params** | **5.4M** | |

### Tile Vocabulary (Internal ↔ Game Mapping)

| Internal ID | Game ID | Type |
|-------------|---------|------|
| 0 | 0 | Floor |
| 1 | 1 | Wall |
| 2 | 4 | Ice |
| 3 | 5 | Ledge_U |
| 4 | 6 | Ledge_D |
| 5 | 7 | Ledge_L |
| 6 | 8 | Ledge_R |
| 7 | 100 | START |
| 8 | 101 | GOAL |
| 9 | 2 | (reserved) |

### Architecture Components

```
Input:
  - tiles: (B, 169) tile indices (possibly masked with token 10)
  - t: (B,) diffusion timestep
  - start_pos: (B,) flat index 0-168
  - goal_pos: (B,) flat index 0-168
  - stop_step_feat: (B, 169, 11) [OPTIONAL] one-hot path stops
  - on_path: (B, 169, 1) [OPTIONAL] binary path mask

Embedding:
  tile_embed: Embedding(11, 256)  # 10 tiles + 1 MASK token
  pos_embed: learned (169, 256)
  start_pos_embed: Embedding(169, 256)
  goal_pos_embed: Embedding(169, 256)
  time_embed: MLP(1 → 256)

Path Conditioning (if provided):
  stop_step_proj: Linear(11, 256)  # Which stop number at each cell
  on_path_proj: Linear(1, 256)     # Binary: is cell on path?

Transformer:
  6× TransformerLayer:
    - MultiHeadAttention(256, 8 heads)
    - LayerNorm
    - FFN(256 → 1024 → 256, GELU)
    - LayerNorm

Output Heads:
  tile_head: Linear(256, 10)   → (B, 169, 10) tile logits
  start_head: Linear(256, 1)   → (B, 169) start logits
  goal_head: Linear(256, 1)    → (B, 169) goal logits
```

### Forward Pass

```python
def forward(self, tiles, t, start_pos, goal_pos, stop_step_feat=None, on_path=None):
    # 1. Embed tiles + positions
    x = tile_embed(tiles) + pos_embed
    
    # 2. Add timestep embedding (broadcast)
    x = x + time_embed(t).unsqueeze(1)
    
    # 3. Add start/goal position context (broadcast)
    x = x + start_pos_embed(start_pos).unsqueeze(1)
    x = x + goal_pos_embed(goal_pos).unsqueeze(1)
    
    # 4. Add path conditioning if provided
    if stop_step_feat is not None:
        x = x + stop_step_proj(stop_step_feat)
    if on_path is not None:
        x = x + on_path_proj(on_path)
    
    # 5. Transformer layers
    for layer in layers:
        x = layer(x)
    
    # 6. Output heads
    tile_logits = tile_head(x)      # (B, 169, 10)
    start_logits = start_head(x)    # (B, 169)
    goal_logits = goal_head(x)      # (B, 169)
    
    return {"tile_logits", "start_logits", "goal_logits"}
```

### Generation Process

```python
def generate(batch_size, device, seed):
    # 1. Initialize all tiles as MASK tokens
    x_t = full(MASK_TOKEN)  # (B, 169)
    
    # 2. Sample START/GOAL positions (one forward pass)
    outputs = forward(x_t, t=T-1)
    start_pos = gumbel_sample(outputs["start_logits"])
    goal_pos = gumbel_sample(outputs["goal_logits"])
    
    # 3. Iterative denoising (T steps)
    for t in reversed(range(T)):
        outputs = forward(x_t, t, start_pos, goal_pos)
        x_0_pred = sample(outputs["tile_logits"])
        
        # Re-mask some positions for next step
        mask_prob = alpha_bar[t-1] / alpha_bar[t]
        keep_mask = random() < mask_prob
        x_t = where(keep_mask, MASK, x_0_pred)
    
    return tiles, start_pos, goal_pos
```

## Appendix C: Problem Space Definition

### Task

Generate a 13×13 ice puzzle grid that:
1. Has exactly one START and one GOAL tile
2. Is solvable (path exists from START to GOAL)
3. Has no stuck positions (every reachable tile can reach GOAL)
4. Has exactly ONE optimal path (unique shortest solution)
5. Optimal path is exactly 10 moves

### Movement Rules

- **Floor (0):** Player moves 1 tile in input direction
- **Ice (4):** Player slides until hitting wall/ledge/floor
- **Wall (1):** Impassable, stops sliding
- **Ledges (5-8):** One-way tiles, can only be entered from specific direction
- **START (100):** Starting position
- **GOAL (101):** Win condition

### Difficulty Philosophy

The game uses a **binary lives system** - player must complete puzzle in exactly the optimal number of moves or they lose that life. Backtracking cost is irrelevant; once you make a wrong move, the life is burned.

Key difficulty metrics (ranked by importance):
1. **paths** (near_optimal_paths) - More paths = more confusion
2. **olap** (path_overlap) - Low overlap = truly different routes
3. **ediv** (early_divergence) - Confusion from move 1

### Data Generation

Training data is generated by the Rust generator which:
1. Randomly places tiles
2. Validates using BFS solver
3. Filters for exactly 10-move unique-optimal solutions
4. Takes 10-60 minutes per puzzle (motivates ML replacement)
