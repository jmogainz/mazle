Mazle pretraining (Python)
==========================

This folder contains a fast, seed‑conditioned one‑shot model for imitation
pretraining on the JSONL dataset generated by the Rust generator.

Key goals
---------
- Deterministic seed -> latent -> grid (matches the RL plan).
- Separate heads for tiles, start, and goal (easy transition to RL fine‑tuning).
- Fully‑convolutional + attention so the model can be extended to variable sizes.
- Optimized for Apple Silicon (M‑series) with MPS support.

Dataset format (one JSON object per line)
----------------------------------------
{
  "seed": "train-000001",
  "width": 15,
  "height": 15,
  "tilesInterior": [[...13x13...]],
  "start": {"x": 3, "y": 10},
  "goal": {"x": 11, "y": 2}
}

Setup
-----
1) One-time setup + bridge build (recommended):
   export UNIQUE_RUNNER_ID=$(whoami)
   cd /Users/jmogainz/mazle/generator-rust && make ml-setup

2) Run pretraining (XL preset by default):
   cd /Users/jmogainz/mazle/generator-rust && make ml-pretrain

Defaults come from `generator-rust/ml/config/pretrain.yaml`. You can override via env vars:
  ML_DATA_COUNT=200000 ML_BATCH_SIZE=96 ML_EPOCHS=8 make ml-pretrain

Override the config file itself (YAML or JSON supported):
  ML_CONFIG=/path/to/config.yaml make ml-pretrain

Pass raw CLI args if you prefer:
  ML_EXTRA_ARGS="--no-amp --batch-size 96" make ml-pretrain

Data path (default)
-------------------
`pretrain.yaml` points to `../data/mazle-train.jsonl` (relative to `ml/config/`).
Override with `ML_DATA=/path/to/file make ml-pretrain`.

Add `--eval-test` to score the held-out test split after training.

One-go script
-------------
This script creates the venv (if missing), installs deps, then runs
pretraining in one step (bridge build stays separate):
  bash /Users/jmogainz/mazle/generator-rust/ml/scripts/run_pretrain.sh

You can override settings via env vars (examples):
  DATA_COUNT=200000 BATCH_SIZE=96 EPOCHS=8 bash .../run_pretrain.sh
  SOLVER_EVAL=0 bash .../run_pretrain.sh

Preset sizes:
- base (fast)
- large
- xl (default, best quality)

Notes for performance (M‑series)
--------------------------------
- MPS is used automatically if available.
- You can enable AMP and torch.compile for extra speed:
  python3 pretrain.py ... --amp --compile

Validation (Rust bridge)
------------------------
To validate model samples against the real Rust solver, add:
  --solver-eval --solver-eval-samples 256 --solver-target-moves 10

The solver evaluation runs on the validation split and reports rates for:
valid tiles, solvable, unique optimal, no stuck, exact target moves.

Ray Tune (hyperparameter search)
--------------------------------
Run a small search on lr/weight_decay/dropout/batch_size:
  cd /Users/jmogainz/mazle/generator-rust && make ml-tune

To also search architecture knobs (slower):
  ML_TUNE_ARCH=1 make ml-tune

By default Ray optimizes `val_loss`. You can change this with:
  ML_TUNE_METRIC=val_tile_acc ML_TUNE_MODE=max make ml-tune

RL migration
------------
The model output heads match the RL plan:
- tiles logits: H x W x K (tile vocab excluding start/goal)
- start logits: H x W
- goal logits:  H x W

The seed is deterministically hashed into a fixed latent vector during both
training and inference, so you can keep the same seed retry scheme later
(seed + attempt_index).
